# 0.6.1 — Simple setup and everyday oil estimates

This release builds on 0.6.0b5.

## Start without a scale

Enter a scent name and choose a bottle size: **30, 60 or 120**, default **60**.
The selected number is used as an approximate starting mass in grams, including
when a product label uses volume. Custom amounts and actual weights remain available.
The default rate is **4 mg per 5 seconds of active spraying**. It is provisional,
not a factory specification or a rate measured for every oil and diffuser.

Consumption follows reported spray duration, pause duration and scheduled time.
Levels 2 and 3 in the example timing table both spray for 10 seconds, with different
pauses; level number is not an oil multiplier. A fresh weighing anchors remaining
mass. Two eligible real weights with sufficient recorded coverage can refine the
rate; nominal size alone never calibrates it. See [bottle guide](../BOTTLES.md).

## Less clutter

Oil grams/percentage, days remaining, scent/bottle, refill status and Bluetooth
health stay available. Technical accounting, timing and connection-age sensors
are optional diagnostics disabled by default for newly registered entities.
Upgrades preserve existing unique IDs and enabled choices. Raw frames and internal
accounting details remain in downloadable diagnostics. Generic Bubble examples use
the simpler popup, practical next-step guidance and the optional setup form.

## Upgrade and rollback

Take a full Home Assistant backup first. Existing rates, balances, IDs and history
are retained. New default-rate provenance and unknown tare are supported by 0.6.1;
b5 and earlier cannot read those new records. Returning to an older version requires
its code **and the matching pre-upgrade inventory backup**. b4 and earlier also lack
the continuous-counter format. Do not delete the integration to fix storage errors.

Install through HACS or extract the integration ZIP into
`config/custom_components/aromatech_ambience/` and restart HA.
Dashboard examples are a separate ZIP; map every
placeholder and update/register the optional JavaScript resource manually. Integration
installation does not overwrite dashboards or change scenting settings.

## Scope and validation limits

These values are estimates, not hardware oil-level or spray-event measurements.
Physical use can differ with oil, device and handling. Uncertainty can hide remaining
mass and forecasts pending a fresh weighing. The default does not eliminate that
safeguard. Experimental multi-slot/minute writes and Always on remain opt-in;
firmware checking and OTA are outside this release.

Local validation and review are recorded in [VALIDATION](../VALIDATION.md):
252 equipped Python tests, 23 frontend tests, and desktop/mobile previews with
all mutations intercepted. Exact-release GitHub tests, HACS and hassfest are
required before publication. Native-form, restart/schedule-boundary and heartbeat
acceptance on an installed 0.6.1 device remain follow-up checks; earlier b5 live
weighing evidence establishes mass anchoring, not a calibrated universal rate.
Publication does not install 0.6.1 or change any diffuser's power, oil or schedule.

# 0.6.0b5 — Continuous estimated usage and Bluetooth health

Home Assistant now advances estimated usage every 30 seconds from the last known
scenting state, schedule and intensity timings. Bluetooth reports confirm those
assumptions; missed reports no longer freeze the counter.

- Independent Bluetooth heartbeat cannot be postponed by lighting updates.
- Estimated cycles, pump-on time and consumption belong to the installed bottle
  and fill. Stored bottles retain their balance and receive no new consumption.
- Atomic accounting checkpoints support restart catch-up once, with uncertainty.
- Confirmed command boundaries can adjust estimates; unknown external changes
  retain an uncertainty window. Weighings anchor remaining mass. Adjustments are
  auditable, including the latest reconciliation in bottle sensor attributes.
- Bluetooth health, last contact and confirmation age remain visible offline.
- Bubble examples retain their shape and oil-status colours, adding confirmation
  and consumption details. These remain estimates, not detected physical sprays.

## Install and rollback

**Take a Home Assistant backup before installing.** This beta migrates inventory
to schema2 while preserving existing IDs, measurements and counters. b4 and earlier
cannot read the new fill format: rollback requires the matching pre-upgrade backup
as well as the older integration code. Do not delete the integration to fix a
storage error. No missing historical usage is automatically invented.

Select **0.6.0b5** under HACS prereleases, download and restart HA. An integration
ZIP is attached for manual installation, plus a separate dashboard-examples ZIP.
Map the example entity placeholders, including the three Bluetooth sensors.
Integration updates do not overwrite dashboards or deliberately change intensity,
scenting power or schedules. Existing Always on mode remains experimental.

After installation, confirm bottle identity and totals, observe two counter ticks
within an active schedule, and check that the next heartbeat resets confirmation
age while normal lighting automation runs. See docs/VALIDATION.md for acceptance.

Validation: 242 equipped Python tests and 19 frontend tests; desktop/mobile browser
fixtures cover healthy/stale/offline/missing states without device writes. Code
review found no blocking issues. Tests use HA stubs; live physical acceptance is
still required before a stable release. GitHub tests, HACS and hassfest must pass
on the exact release commit before publication.

# 0.6.0b4 — Always on toggle and saved schedule

The new **Always on** switch replaces b3's one-shot **Set 24-hour schedule** button.

- **On:** save all current schedule slots durably, then run the selected intensity's
  spray/pause cycle every day. Other slots are temporarily disabled.
- **Off:** restore the saved days, times and enable flags, keeping the current
  intensity. The saved schedule survives Home Assistant restarts.
- Timed controls are disabled while Always on is active. **Scenting** remains the
  independent master switch; mode changes do not switch it on or off.
- Failed writes retain the backup. Unexpected external schedule edits are rejected
  rather than overwritten. Pending recovery exposes a dashboard restore action.

Enable **Experimental schedule writes** in integration options before first use.
The switch remains visible online when this option is off; attempting to enable
Always on explains the required setting. Turning it off can restore an existing
managed schedule even if the option was subsequently disabled.

Physical 24-hour operation still needs validation. If an all-day schedule was
created externally or by b3, there is no saved timed schedule to invent: first set
a timed schedule in the vendor app, then use the new toggle.

## Install

Select **0.6.0b4** in HACS prereleases, download and restart HA. An integration ZIP
is attached for manual installation. Existing bottle records, measured weights,
rates and consumption counters are retained. Installation does not activate
Always on or change intensity. The obsolete button registry entry is removed.

The separate dashboard-examples ZIP includes the Bubble switch and grey read-only
schedule view. Map `switch.replace_me_always_on` and the other placeholders, and
use Card-mod for grey styling. Integration updates do not overwrite dashboards.

The beta includes b3's consumption-accounting fixes. Offline tests cover durable
save-before-write, failures/restart, multi-slot restoration, conflict detection,
experimental gates, native controls and master-power preservation. GitHub tests,
HACS and hassfest must pass on the exact release commit before publication.
